# TQX 程序与状态的 BO 写入和读回

2026-09-28。本轮新增 `kernel/mt_tqx_upload.h` 和 GEM 内部 `upload_tqx_stream`。
所有实测使用 RAM 后备；主模块未加载，没有真实 GPU 上传、执行、恢复或 Host 操作。

## 实现

在上一轮七对象的堆、VM 和物理别名检查后，将已经验证的命令镜像分散写入五类 BO：

| BO | 写入范围 | 内容 |
|---|---:|---|
| command | 4096 字节 | 80～320 字节命令，其余清零 |
| shader | 20480 字节 | 20096 字节程序库，其余清零 |
| PDS code | 4096 字节 | 176 字节 PDS 程序库，其余清零 |
| PDS state | 4096 字节 | 初始状态及每块 80 字节状态/常量，间隙与余量清零 |
| texture | 4096 字节 | 每块 64 字节纹理/sampler，其余清零 |

合计九页、36864 字节。每页通过 I/O 回调写入并完整读回比较，
生产 GEM 路径调用现有 `mt_bo_vram_write/read`，使用 BAR `memcpy_toio/fromio`
及已有 barrier，不把 I/O 地址当普通 RAM 指针。

VM 绑定可位于 BO 内的非零偏移：先解析实际物理区间，再减去 BO 后备起始地址，
得到写入偏移。写入范围之外的 BO 内容保持不变；源和目标数据不由上传器修改。

软件记录 296 字节、页记录 16 字节和根地址导出 16 字节作为单独的 328 字节结果返回，
不写入程序 BO，也不当成固件 DMA 描述符。9504 字节工作区由 GEM 在堆上分配，
避免在内核栈上放置两个 4 KiB 页面。

## 引用与失败边界

GEM 在整个上传期间持有七个独立句柄引用；在公共会话锁下完成验证和全部 I/O，
解锁后释放引用及工作区。已经存在 CPU/GPU 使用者的任一资源、sealed VM 或
active VM 均在首次写入前拒绝。上传不修改 `vm.uploaded`、不封存或发布 VM，
也不会自动取得供异步提交使用的 GPU 引用。

参数和映射错误发生在写入前。I/O 失败或读回不符时，返回错误且不改输出记录；
**BO 可能已经被部分写入，不能声称内容回滚**。后续必须完整重试或丢弃这些资源，
不得凭旧的输出记录继续提交。完整重试会重写九页，包括从多块缩减为单块后的旧状态。

## 验证

- 增强 `verify-tqx-heaps.py`：144 组布局中，独立按原始指令分配返回的相对地址
  放置每一段状态，再将真实 `140119250` 构造的程序库拆成两个堆；逐字节核对
  整套 36 KiB 页面及输出保护区。该核对没有调用 C 页面打包器生成期望值。
- 新增 `tqx_upload_test.c`：实际 BO/VM/上传代码使用 RAM I/O，覆盖非零 BO 偏移、
  首尾保护区、源/目标不改、九页写读次数、45 个写/读/损坏读回/map 失败位置、
  七资源各自的 CPU/GPU busy 拒绝、sealed/active VM、失败输出保持、完整重试
  以及旧状态清除；ASan/UBSan 通过。
- GEM 模型测试覆盖工作区分配失败、七个句柄查找位置失败回收，以及查找期间
  关闭所有用户句柄后上传仍能完成，最终引用和分配释放平衡。
- 集成检查增至 10 类并通过；主模块 W=1 构建无警告，`mt_guest` ABI 与保留模块一致。
- 真实 Linux GEM/VM 的内核 RAM 检查增至 **114 项**，九页写读以及人为读回损坏
  检测通过；RAM 后备分配/释放 10/10。临时模块已卸载，无新增内核错误，
  前后仅有 QXL card0、无 MTT render 节点。

证据：`tqx-heap-validation.json`、`runtime-integration-build.json`、
`gem-kernel-validation.json`。真实 kernel RAM 测试调用 RAM 回调；生产 BAR I/O
路径完成编译但未在设备上运行，不能据此宣称 GPU 已接受程序。

## 下一段反编译线索

继续追到实际 TQX DMA 序列化入口 `14004d7bc → 14004e924`：当命令种类为 5、
元数据长 `0x50`、标志位 2 清零时进入。它从 `14004d188(command)=command+0xdc8`
读取当前 296 字节软件记录，写 `0x67` 头、section 类型 3、每条 `0xc0` 公共数据，
并按设备版本追加 `0x28` 或 `0x38` 字节。

另一条分页整理入口为 `14001a064`：输入步长 `0x170`，输出同样标注 `0x67`，
处理单独的 `0x400` 字节状态区域。两条路径需要结合调用者和布局初始化继续确认，
不能把此前 CE 的 `14002171c/140019f10` 转换直接套用到 TQX。
