# 事件分派与空提交 fence 路径

2026-09-28。继续基于现有反编译库适配，不处理恢复。本轮没有替换主模块、
操作宿主或向 GPU 发命令。实际加载的自测模块只访问普通 RAM，现已卸载。

## 原始指令依据

`mtkm64.sys:14000be34` 遍历六个 DM 的 64 项事件环，每项 24 字节。汇编确认第三个
回调参数是完整事件指针，伪 C 的部分调用省略了该实参。

| 项目 | 已确认行为 |
| --- | --- |
| 事件 +4 的 DWORD | 类型：0→e6a4，5→e7a4，0x50→e784，0x101→e5c8 |
| 事件 +8 的 DWORD | 普通完成的 32 位 fence 编号 |
| 14000e6a4 | 有待完成记录且编号等于最早一项才更新完成值、通知并推进软件索引 |
| 类型 5 | 单独的抢占处理，不能当作普通任务成功 |
| 类型 0x101 | 受节点模式限制的故障分支，尚未移植 |
| 14001475c 的 NULL 描述符分支 | 80 字节包清零，+0x0c=100，+0x48=fence，提交到 ring0 |
| 1400238cc | 共享页 0 的 +0x330 DWORD **等于 1** 时暂停提交 |

其余事件字段本轮保留原始值，不推测为时间戳、地址或上下文号。空提交包来自真实
NULL 描述符分支；名称不意味着本机固件已接受它。参考路径还包括时间/共享统计
（c92c/c818/239a4）、WDDM 通知及诊断历史，这些调用在 oracle 中被截获或建模，
不是完整提交初始化流程的等价实现。

## Linux 实现

`mt_fw_event.h` 提供类型解码、普通完成匹配、空提交编码及事件消费者。每次读取
当前 head 快照，按总预算有界处理；先完成回调再确认 tail。回调失败时仅确认此前
已成功处理的记录，失败记录保持待处理。检查游标小于 64，不清除事件内容或敲门铃。
这比参考无条件消费未知/不匹配事件更严格，目的是避免丢失目前尚不能解释的完成。

`mt_marker_fence.h` 为 DM1..5 管理空提交待完成队列，DM0 留给固件控制。
每 DM 最多 63 项。队列 head 发布前先建立软件所有权；已验证的队列函数仅在写入前
返回错误，所以失败时可移除未发布项。成功后待完成队列独立持有 dma_fence，关闭
调用者引用或等待超时不会将它释放。只有所属 DM 最早项的编号匹配普通完成事件才
signal 并归还待完成引用；错序、重复、抢占、故障和未知类型均不能完成该项。

每个 fence 自带锁和模块引用，可以在完成后独立于设备对象继续存活；最后引用经
RCU 释放。编号从 1 开始，失败允许留下空号，本会话不重用 32 位 wire ID；用尽时
返回 EOVERFLOW。没有超时强制完成、重置队列或未经确认释放硬件会话的接口。

主模块外层对象加入 fence 管理器、只读 completions 统计和运行态消费者。没有
待完成项的事件继续保留到诊断记录；有待完成项时走匹配和 signal。消费者遇到错误
仍保留事件与待完成项，运行态记录 event_result 并停止后续消费。原连接试验使用的
事件保留路径未改动。

每次实际提交还必须通过运行态门控：上下文已发布、连接和资源保持、RPC 服务运行、
健康值非零、Guest2/FW2、started，以及共享暂停字段不为 1。暂停返回 EAGAIN，
不在会话锁内循环等待。目前 `ready` 始终关闭，没有公开开启入口；后续必须先完成
节点/任务上下文初始化及实际接受验证，不能仅修改 ready 字段绕过这些工作。

## 验证

`scripts/verify-fw-events.py` 使用 Unicorn 执行允许范围内的 Windows 原始指令：

- 384 个六 DM/各游标位置的分派案例，覆盖环绕与未知类型，核对回调参数和完整队列；
- 80 个普通完成匹配案例，覆盖空/非空、相同/不同编号、边界编号与软件索引环绕；
- 64 个空提交包逐字节一致，8 个共享暂停与空指针案例；
- 8 个非法游标/非普通完成拒绝案例，以及回压、预算和中途失败的 tail 保留测试。

结果：[firmware-event-validation.json](firmware-event-validation.json)。

`kernel/selftest/mt_fence_selftest.c` 在真实 Linux dma_fence 上执行提交和事件 C 代码，
队列、寄存器、doorbell 都由 RAM 替代。165 项检查通过：状态门控、损坏/满队列回滚、
提交包字段、回调与零超时等待、错序/重复/错误类型拒绝、消费者中途停止、调用者先
释放、32 位编号用尽，以及 63 项待完成上限。共正常完成 67 个模拟空提交，已注册
回调仅调用一次。没有新增 WARNING/BUG/Oops；自测模块卸载，DRM 节点集合保持不变。
见 [fence-kernel-validation.json](fence-kernel-validation.json)。

集成测试还直接提取并编译主模块真实提交门控函数，用非零 trial 结构偏移验证回调
参数和读取路径，避免混淆 mt_guest 与 mt_fw_trial 指针。主模块 W=1 构建、共享 ABI
和既有运行/GEM/BO/VM 回归通过，见 [runtime-integration-build.json](runtime-integration-build.json)。

```sh
python3 scripts/verify-fw-events.py
python3 scripts/verify-runtime-integration.py
# --run 才加载并卸载 RAM 自测模块：
python3 scripts/verify-gem-kernel.py --kind fence --run
```
