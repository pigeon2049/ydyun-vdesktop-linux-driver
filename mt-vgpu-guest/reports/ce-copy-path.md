# 复制引擎线性载荷与 GEM 映射检查

本轮沿命令生成库追踪到具体复制指令，新增 `kernel/mt_ce_copy.h`，接入 GEM 内部
`prepare_copy`。没有进行恢复或宿主操作，也没有向显卡提交命令。

## 调用链与版本区分

辅助上下文 `14000f008` → `140020a1c` 创建命令生成库的平台、设备、队列和资源管理器。
内置表 `1402a6af0` 的四组 (引擎, 队列类型, 描述符任务类型) 为：
`(5,5,1)`、`(3,3,9)`、`(4,4,5)`、`(0,0,11)`。这些不等同于固件 DM 编号。

平台创建链：`140042064` → `140045ab8` → `14004537c` → `140045298`，
平台 vtable `1402b0fd0`；设备 `14004c518` 的 vtable 为 `1403c4d40`。
先前 `14001fdd0` 创建的是库队列对象，不能把它的 vtable 当成命令缓冲区接口。
真正命令缓冲区由 `14001a3ec` → `140021580` → 设备 vtable+0x108
(`140092c4c` → `14008d694` → `14008d2b0`) 创建。

复制模块保存在设备+0x360，由 `14005331c` 按 CE 版本选择：

| CE 版本 | 模块构造 | 命令对象构造 | 命令 vtable | 线性复制（vtable+0x58） |
| --- | --- | --- | --- | --- |
| 1/2 | 14009cb90 | 1400dcc1c | 140bb51d0 | 1400df1a4 |
| 3 | 14009e2cc | 1400e47ec | 140bc1100 | 1400e5df4 |

版本 1/2 使用相同指令编码函数；本轮没有据此猜测本机实际 CE 版本。

## 40 字节线性复制载荷

每条指令含 5 个 little-endian u64：header、目标地址、长度减一、源地址、长度减一。

- CE1/2 基本 header 为 `0x2010048000000000`；长度字段仅保留低 32 位。
- CE3 基本 header 为 `0x20100e0000000000`；长度字段保留 64 位。
  其中格式编码由原始 `1400c57c8(0x1a)` 返回 1，已执行确认。
- 地址字段保留低 48 位；CE3 目标字高位固定 OR `0xc000000000000000`，
  CE1/2 的同样高位受平台 predicate `14004c2fc` 控制。
- header bit31/32 来自源/目标对象描述符+0x4c 是否等于 2；bit59 来自内存属性
  predicate，CE1/2 还受平台能力 predicate 控制。具体 Guest 缓存/内存域策略未确定，
  因而代码只使用对应字段控制名，不擅自命名成物理/虚拟地址或一致性开关。

encode 只重现载荷格式；prepare 额外要求非零且能放入 BO 的长度、40 位 GPU VA、
源和目标分别属于指定 BO 的完整 VM 绑定，同一显存管理器。检查实际后备地址区间，
即使两个 VA 不同，只要它们映射的物理存储重叠就拒绝。失败保持输出不变。

GEM prepare_copy 取得同一文件内源/目标对象引用，验证所属设备/管理器，在会话锁内
执行准备，解锁后归还引用。可处理同一 BO 的不重叠范围，拒绝跨文件、错误对象、
未映射、越界及重叠别名。输出仍只在 CPU 内存，未写命令 BO 或上传 GPU。

## 验证

`scripts/verify-ce-copy.py` 在隔离 RAM 中执行两个原始编码函数，**192 个载荷**与 C
实现逐字节一致，覆盖 CE1/2/3、所有 16 组字段控制、宽地址、1 字节至超过 32 位的
原始长度字段、输出尾部保护和无效参数拒绝。原始地址加法和格式 helper 直接执行；
流准备、屏障、缓冲区分配/提交以及平台/内存属性 predicate 被显式建模。
这验证了独立复制载荷，不验证完整指令流或硬件行为。

GEM ASan/UBSan 模型测试新增文件隔离、双对象引用回收、同一 BO 复制、别名重叠、
源/目标映射和长度边界检查。全部集成回归通过；W=1 构建无警告，`mt_guest` ABI
对照通过。真实内核 GEM + RAM 测试通过 **24 项**检查，两次分配/释放平衡，
临时模块已卸载，主模块未加载，PCI 和 DRM 节点状态未改变。

## 下一步与明确缺口

**40 字节载荷不是完整可执行流，硬件加速仍未实现。** 目前未启用任何工作提交。
编码前的 CE1/2 `1400e33e4`/`1400dd6ac` 与 CE3 `1400e8ef4`/`1400e4d04`
负责待发同步和流初始化，涉及跳转、分块、地址对齐、起始状态；同样不能简单省略。
其中初始化写入跳转 opcode `0x4...`、控制字 `0x5000000000000001`，并设置
对象+0xfa0/+0xf90 等流元数据，需要进一步逐条验证。
重叠范围屏障分别是 `1400dd39c` / `1400e4b7c`；可选的 24 字节前缀取自
对象+0x1020，低 16 位设为载荷 u64 数量 5。后续需继续还原完整起止/同步/前缀、
确认本机 CE 版本与内存属性，再结合已实现的 VM/context/job/fence 路径。
