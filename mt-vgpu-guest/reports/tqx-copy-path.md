# 本机 TQX 线性复制：拆块、几何和操作选择

本机 0222 的参考库 transfer_version=1、CE_version=0，详见
[平台选择证据](device-profile-path.md)。本轮新增 `kernel/mt_tqx_copy.h` 和
GEM 内部 `prepare_tqx_copy`。它们生成 CPU 暂存计划，尚不是可提交的 GPU 命令流。

## 参考入口

`140052864(1) → 14009bcb0 → 14009bb68` 创建传输模块，vtable 为 `140603ff8`。
模块 `+0x28 → 14009bdb0 → 1400d9b08` 创建命令对象，最终 vtable 为 `140baef10`。
其 `+0x58 → 14011acfc → 14010f034` 是线性复制路径。

每个 24 字节区域提供源偏移、目标偏移和长度。`14010f034` 取资源基址加偏移，
把 `{源 VA, 0}`、长度、unit=1、align=1 传给 `1400a624c`，不是把源和目标同时
传入拆块函数。因此这里的对齐是 16，与目标低位无关。

长度大于 4096 且源未对齐时，先产生不足 16 字节的前缀；剩余长度分为高 5 位、
中 15 位和低 12 位三组。每块再由 `1400a5314` 转换为元素字节数、宽和高，
总计最多四块。短且未对齐的低位单块保留 byte 元素。
支持长度 1 至 0xffffffff，并加上 Linux 当前 VM 的 40 位地址范围限制。

每块由 `1400a5740` 生成完整 104 字节 surface 和 168 字节 state，格式常量取自
参考表 `14071d9e0`；`1400571e0` 生成 state +0x80 的元素大小编码。
源和目标共享几何，地址分别加块偏移，矩形为 `{0,0,width,height}`。
`140114418` 对此单层、同尺寸复制选择操作：元素 1/2/4 字节为 8，8 字节为 0x10，
16 字节为 0x15。计划保留这些操作号，供后续 job 构造使用。

## Linux 接入和验证边界

计划包含原请求、最多四个 24 字节块、操作号、surface、state 和后续补齐的
源纹理描述符，总长 1488 字节。源描述符验证见 [本轮记录](tqx-texture-path.md)。
GEM 持锁查找两个句柄，要求同一个设备/对象管理器及有效 VM 映射，检查完整源/目标
范围与物理后备重叠。成功只写 CPU 输出；失败不修改输出；每次查找都平衡释放引用，
包括源和目标使用同一个句柄的情形。不上传页表、不写 BO、不持有 GPU 使用引用。

`scripts/verify-tqx-copy.py` 使用固定哈希的参考 PE 和限定指令范围：

- 432 组地址/长度覆盖全部源低四位、4096/32768 边界、三组长度边界与随机值；
  原始拆块、surface 和 state 与 Linux 输出逐字节一致。
- 同样 432 组执行外层 `14010f034` 和真实 `140114418`，在 `140113c08` 入口捕获
  地址、几何、矩形及操作号并对照。区间同步及最终 job 发射使用模型，不把这些
  模型返回值算作协议验证；memcmp/memcpy/memset 和栈 cookie 是 CPU 辅助模型。
- 10 个无效输入/容量/空指针拒绝案例，以及输出尾部保护检查通过。
- GEM 集成测试在 ASan/UBSan 下覆盖归属、查找失败、平台拒绝、范围、别名和引用；
  真实内核 GEM/RAM 测试覆盖计划构造及别名拒绝。主模块 W=1 构建、ABI 对照通过。

以上均不执行显卡指令。主模块未加载，临时 RAM 自测模块运行后卸载。
证据：[原始指令对照](tqx-copy-validation.json)、[集成验证](runtime-integration-build.json)。
