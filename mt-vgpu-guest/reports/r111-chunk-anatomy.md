# r111：chunk 解剖——读的是 next-chunk 数据区（内容签名已取）

r109 越界机制的 chunk 级确认（gdb 直接读堆元数据）：

```text
P-0x08 = 0x41   (chunk size 0x40, usable 0x38=56 ✓ 与 malloc_usable_size 一致)
P+0x38 = next chunk 头；P+0x50/+0x54/+0x58 = next+0x18/+0x1c/+0x20（数据区）
next 内容签名：{+0x18: 0x3000, +0x1c: 0, +0x20: 0xf}
```

即：读的是**相邻活对象**的数据区（非空闲块——tcache fd 应为堆指针），
其 `+0x1c` 槽恰为 0。喷洒打不进去的原因也彻底清楚：
我方 spray 缓冲（0x…67cd0 区）与 P（0x…6af80 区）差 130KB，
根本不在同一分配代——UMD 内部在两者之间做了大量分配。

## 下一步（单点）

按内容签名 `{0x3000, 0, 0xf}` 反查邻居对象类型（devmem/heap/frag
描述三选一；`0xf`=15 极似堆数、`0x3000` 极似尺寸），
再找它的分配点——改那个分配的输入，即改邻居内容。
备选捷径：既知读的是 next-chunk 数据，若能让 UMD 在 P 之后
分配一个**我们可控内容**的对象（如带 pattern 的 PMR 描述），
一次即转正——比追类型更快，值得先试。
