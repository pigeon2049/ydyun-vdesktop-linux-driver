# CE 软件记录到 Windows 分页复制描述符

**后续平台核查**：本机 0222 的 CE 版本为 0，本文结果属于通用 CE 参考，
不适用于本机复制路径。Linux 入口已拒绝本机 CE 请求，适配已转入
[TQX](tqx-copy-path.md)，证据见 [平台选择](device-profile-path.md)。

继续 Guest 端适配，恢复问题暂不处理。本轮新增 `kernel/mt_ce_paging.h` 与 GEM
内部 `prepare_copy_paging`，连接上一轮 CE3 命令段与一条已确认的分页封装路径。
**这是 CPU 暂存实现，尚未完成可向固件提交的完整工作负载，也未获得硬件加速。**

## 路径与纠正

进一步解析复制队列及引擎实例的 vtable，确认：

- 队列 `1405f7ba0` 的 +0x108 → `140050bfc` 是返回 0 的空实现。
- `1400d3a9c` 的 engine type3 从设备 +0x360 取得复制模块；CE3 模块
  `14060fb18` 的 +0x20 → `14009e454` → `1400ea0e0` 创建引擎实例。
- 实例 vtable `140bc72d0` 的首项 → `1400d61dc` → `1400fb8d4`；后者回调
  命令对象 +0x3c0。CE3 命令表 `140bc1100` 的这个回调是空实现 `14004c138`。
  因此不能把这条泛用队列路径假定为记录的完整序列化器。
- 更直接的已确认路径是命令表 +0x30 → `1400e2690`，由 `14002171c` 调用，
  再由 `140019f10` 整理分页描述符和单独的状态槽。

`14002171c` 的伪 C 错把间接调用的首参数显示为 0。检查原始汇编，RCX 保留
命令对象指针；本轮原始指令测试使用真实 vtable 分派，完整执行这次调用，
没有用一个固定返回值替代导出过程。

## 已确认字段

`1400e2690` 要求恰好一条记录。它生成 48 字节导出结构：

| 导出偏移 | 来源 |
| --- | --- |
| 0x00 | 记录数 1 |
| 0x08 | 软件记录 +0x00 |
| 0x10 | 软件记录 +0x10，命令段根地址 |
| 0x18 | 软件记录 +0x08，原附加状态地址 |
| 0x20 | 软件记录 +0x20 |
| 0x28 | 软件记录 +0x28 |

`14002171c` 把导出 +8/+16/+24/+40 分别写入分页描述符
+0x128/+0x138/+0x130/+0x70；导出 +0x20 不被此适配器复制。

对单个、初始清零的 0x150 字节描述符，`140019f10` 产生：

| 描述符偏移 | 结果 |
| --- | --- |
| 0x1c | 0x69 |
| 0x28 / 0x2c | 0x48 / 1 |
| 0x48 / 0x50 | 4 / 0x60 |
| 0x58 | 0xe8 |
| 0x64 / 0x68 / 0x6c | 0x08000000 / 0x18 / 1 |
| 0x70 | 软件记录 +0x28，当前限定 CE3 序列为 24 |
| 0x128 | 软件记录 +0，当前限定序列为 32 |
| 0x130 | **重新定位的状态槽 VA**，覆盖原命令尾部状态地址 |
| 0x138 | 命令段根 VA |

单独状态槽的前两个 qword 为 `[记录+0x28, 0]`。原始函数按上下文 variant
推进分配游标 32 或 128 字节，实际只写 16 字节。本实现暂存 128 字节清零槽，
避免未确定 stride 时少预留空间；没有自动为本机选择 variant。

此 336 字节分页描述符和已有 80 字节固件队列包是不同层次。
这里重现的是指定初始化条件下的参考转换，不证明其余 Windows 提交元数据可省略，
也不证明固件命令 VA 可以直接指向任意一个中间结构。

## Linux 接入

`mt_ce3_paging_prepare` 输出 896 字节 CPU 暂存包：176 字节命令段、256 字节
库记录、336 字节分页描述符、128 字节状态槽。库记录仍只是软件中间数据。

调用者提供三个 VA：命令段、描述符和状态槽，均需实际属于命令 BO 的 VM 映射；
两个数据 VA 分别属于源/目标 BO。检查 40 位范围、对象后备范围、管理器、对齐，
并逐对排除五个区间的后备地址重叠，包括不同 VA 对同一存储的别名。
输出失败时保持原内容，成功时也不修改 BO、上传页表、持有 GPU 引用或发布命令。

GEM 的 stream/paging 接口共用三句柄引用处理，同一文件里的同一句柄可出现三次，
每次查询分别持有和归还引用。新增 ASan/UBSan 检查覆盖组件互相覆盖、组件覆盖
源/目标、别名、映射末端、40 位越界、对齐、容量、空请求、缺失句柄及文件隔离。
