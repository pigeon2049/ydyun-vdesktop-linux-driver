# TQX 九对象检查与十一页上传

新增 `kernel/mt_tqx_submission.h` 和 GEM `upload_tqx_submission`。接口在写入前
核对完整九对象的映射、归属、物理别名及占用状态，然后上传程序和 DMA 并读回。
现已把此前独立 CPU DMA 编码接到 BO 写入路径，但没有发布 GPU 任务。

后续已接通 [原子准备、长期引用与 fence 交接](tqx-work-lifetime.md)；
下文保留本上传接口本身的行为及当时验证范围。

## 资源与行为

| 对象槽 | 所需映射 | 上传行为 |
| --- | --- | --- |
| 0：命令 | 4096 | 上传1页 |
| 1：shader | 20480 | 上传5页 |
| 2：PDS code | 4096 | 上传1页 |
| 3：PDS state | 4096 | 上传1页 |
| 4：纹理/sampler | 4096 | 上传1页 |
| 5、6：复制源和目标 | 覆盖复制范围 | 不作CPU写入 |
| 7：DMA描述符 | 8192，普通堆 | 上传2页，包含末尾填充 |
| 8：独立引擎状态 | 4096，普通堆 | 保留已有内容 |

共11页/44 KiB写入并逐页读回。支持非零BO绑定偏移。
九对象在整次操作中都保留GEM引用，持有共享会话锁；未取得核心数时返回`-ENODATA`。
核心数直接取已安装的Guest信息页结果，调用者不再另传核心数。

现有七对象检查继续复用。新增加的DMA和引擎状态分别与之前全部对象比较物理区间，
覆盖15对新增别名关系。缺失或短映射、任一CPU/GPU占用、已封存或活跃VM均在写入前拒绝。
这个接口不会改动VM的uploaded/sealed/active标志，也不获取长期GPU引用。

成功返回24字节真实DMA提交视图：GPU DMA VA、有效字节数及标志。
I/O失败保持调用者结果不变，但已写BO可能含部分新内容；必须完整重试或丢弃缓冲区。
GEM查找失败、堆工作区分配失败和中途关闭句柄均回收临时引用。

## 为什么保留引擎状态

原始 `0931b8` 对usage0/flags`0x10100`选择类型2。实际平台回调
`0219d0 → 041cc4`把它称为`ctxState`，并从已有上下文资源取得CPU/GPU地址和大小。
它既不重新分配，也不改写状态数据。现已原始指令执行验证两条地址取得路径，
覆盖1～8核心、零和非零预存内容，共32组完整状态内容保留检查。

进一步静态追踪 `00f008`：创建的`0x118`字节平台对象持有该资源，`+0xf8`
记录常规分配描述符，`+0x100`记录另一种映射。常规路径调用`01e000`请求
`0x5000`字节、`0x80`对齐，后者经`01df28`及系统分配回调创建后备并映射VA；
另一条路径经`022218 → 0278a8/027fb4`映射提供的上下文状态资源。

因此不能在每次上传复制命令时清零引擎状态。Linux现有`mt_bo_create`仍会按本地策略
清零新BO，但**硬件初始状态的完整语义尚未证实**；本阶段不以新BO清零代替该证明。
也未迁移现有Windows上下文或尝试GPU恢复。

## 验证与边界

`verify-runtime-integration.py`现在运行12组测试，相关ASan/UBSan通过；
W=1主模块无警告，共享`struct mt_guest` ABI与保留模块一致。新增覆盖：

- 55个写入/读取/读回损坏/映射失败注入，包括两个DMA页。
- 18个CPU/GPU占用拒绝，15对新增物理别名拒绝；均无提前写入。
- 新资源缺失与短映射、非零BO偏移、前后保护区、源/目标和状态内容保留。
- 完整重试及多核心DMA长度；输出视图确实指向DMA分配区。
- GEM九个位置查找失败、工作区分配失败、缺少信息页配置，以及九句柄全部在查找后
  关闭的场景，引用和DRM对象最终释放平衡。

`verify-gem-kernel.py --kind gem --run`：**138项真实内核RAM检查通过**，
12次后备分配和12次释放。上传后DMA内容正确，预存`0x5a`状态页完整保留。
临时测试模块已卸载，主模块未加载，PCI仍未绑定，只有QXL card0。

`verify-tqx-engine-state.py`补充32组平台回调原始指令检查；此前144组DMA字节对照
仍是底层编码依据。机器可读结果分别保存在`runtime-integration-build.json`、
`gem-kernel-validation.json`和`tqx-engine-state-validation.json`。

尚未完成硬件加速。生产BAR上传未在设备上执行；状态初始语义、上传后到实际任务的
资源持有与fence完成释放、完整上下文发布和GPU执行仍需接通。返回的视图本身不表示
对象已为异步任务持有，不能直接用裸VA绕过现有工作任务准入。
