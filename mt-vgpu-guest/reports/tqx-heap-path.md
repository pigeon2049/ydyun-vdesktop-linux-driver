## 结果

新增 `kernel/mt_tqx_heap.h`，从五段 GPU VA 导出完整 TQX 编码输入，
不再要求上层自己填写 shader/PDS 相对地址和纹理描述符索引。
GEM `prepare_tqx_stream` 在文件句柄归属、对象来源、VM 映射、完整资源范围及
物理别名检查通过后，生成现有 1312 字节 CPU 命令镜像。

这不是自动显存分配器或提交接口。调用者仍须创建/绑定五个资源范围及源、目标 BO。
本轮真实内核测试使用普通 RAM 后备，未将页表或程序上传 GPU，未注册新的 DRM 节点。

## 编号证据

| 用途 | 分配池 kind | resource usage | 库内部堆 | 外部堆 | 平台分配类型（flags=0） |
|---|---:|---:|---:|---:|---:|
| 命令页 | 0 | 0 | 0 | 0 | 0 |
| shader | 3 | 1 | 3 | 2 | 6 |
| PDS 与复制常量 | 4 | 2 | 4 | 1 | 4 |
| 纹理/sampler | 5 | 9 | 8 | 10 | 3 |

这些编号不能互换。静态分配描述符由 `1400d040c` 设置 usage。
`140092db8 → 1400931b8` 选择平台分配类型；flags 会影响普通内存和 PDS 的选择。
真实资源构造链 `140092bec → 1400d3054` 安装虚表 `140b81ba8`，
其 `+0x38` 为 `1400d30f0`，经设备 `+0x1a0 → 140092b50/14008ce98`
选择内部堆，并由 `1400a1bd8` 初始化资源 VA。

命令 allocator 的构造参数 `5` 是另一套索引。实际虚表 `141021938+0x28`
指向 `140045374`，返回池 0；`1400fcb54` 将此返回值传给 `1400d1bcc`。
因此命令页使用普通堆，不能因为构造参数为 5 就放入纹理堆。

`140093494` 把外部堆表转为内部堆，`140092938` 提供 base/end，
`1400a21f8` 返回 `resourceVA + offset - heapBase`。
新对照脚本执行上述资源初始化、堆选择和减法原始指令，不再直接填写资源的内部堆号。

## 本机模式 0 的可用范围

复用此前已验证的 `mt_guest_plan_heaps`，再次执行 `14002a34c → 14001ccd8`
（mask `0x1ef9`）核对保留区。以下 end 为不可包含的上界：

| 外部堆 | base | 可用 end | 尾部保留 |
|---|---|---|---|
| 0 普通 | `0x40000000` | `0x8040000000` | 0 |
| 1 PDS | `0x8100000000` | `0x81ff800000` | 8 MiB |
| 2 shader | `0x8400000000` | `0x84ffe00000` | 2 MiB |
| 10 纹理 | `0xf000000000` | `0xf0ffe00000` | 2 MiB |

两个 PE 表 `141030d90`、`141030fa0` 中这四类原始 base/size 一致；
当前只启用已核实的 family2/transfer1、模式 0 规划，不据此声称其他模式整体可用。
Linux 检查整个映射范围和 40 位地址上限，而非只检查起始地址。

## Linux 页内布局

五个资源范围依次为：命令 4096、shader 20480、PDS code 4096、
PDS state 4096、texture 4096 字节，全部页对齐。
shader 范围覆盖参考 family2 的 `0x4f00` 分配；已提取程序本体为 `0x4e80` 字节。
PDS code 和 state 禁止重叠，并排除固件初始化保留尾部。

PDS state 的前 16 字节存初始 PDS；随后每个 job 使用 80 字节：

- 相对该 job 起点 +0：36 字节执行状态，16 字节对齐。
- +36：20 字节复制常量，4 字节对齐，编码时使用完整 GPU VA。
- +64：16 字节常量装载状态，16 字节对齐。

每个 job 的源纹理/sampler 占纹理页中的 64 字节；编码索引为
`(descriptorVA - textureHeapBase) >> 4`。最多四块，共用一个初始 PDS。
这些紧凑放置是 Linux 分配策略；原始 Windows 分配器的地址/OS 分配仍以 RAM 模型代替。
原始 job 构造器接受此策略后产生相同命令和状态，未把策略描述成参考驱动的固定布局。

## 资源归属与失败行为

`prepare_tqx_stream` 对七个句柄逐一取得独立 GEM 引用，核对当前文件、DRM 设备、
GEM 回调和 store，持会话锁验证每个指定 BO 的 VM 绑定，最后释放全部临时引用。
五段资源按完整页范围检查；源/目标按实际复制长度检查。
七个物理区间任意两者重叠均拒绝，即使 VA 不同或调用者重复使用同一句柄。
所有失败保持输出不变。成功只意味着 CPU 暂存完成，不持有供异步 GPU 执行的引用。

接入主模块暴露了旧组合编码器 2256 字节栈帧警告，已将 job 的内部片段编码
写入事务性本地镜像，避免重复临时 job；公共入口的失败不修改输出语义保持不变。
