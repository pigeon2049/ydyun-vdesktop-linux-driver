# TQX Guest 核心数来源与主模块接入

已确认 TQX 布局核心数来自 Guest 设备信息页 `+0xc9c`，并接入主模块。
此前保存的本机 `device-info.bin` 解析结果为1；本轮未重新查询设备或发送GPU任务。

## 反编译与原始指令证据

平台主对象通过 `1400222b4` 创建，内部平台对象从主对象 `+8` 开始。
这个8字节差异解释了此前只搜索主对象 `+0x94` 写入时遗漏初始化的原因。

`1400254dc` 调用 `140025338`。在内部平台对象 `+0x44 != 0` 的 Guest 分支中：

```
info = *(platform_inner + 0x1cb0)
*(platform_inner + 0x8c) = *(u32 *)(info + 0xc9c)
```

因此主对象 `+0x94` 就是该信息页字段。随后：

1. `1400205ac → 140042000 → 1400228b4` 将主对象 `+0x94` 送到查询结果 `+0x1c`。
2. 设备查询区起始为 `device+0x3f60`，所以该字段在 `device+0x3f7c`。
3. `14004d558` 将它安装到 `device+0x3b4`，由 DMA 布局和引擎状态大小计算使用。

原始 Guest 分支只做内存读取/复制，不读取本地核心寄存器。数值并非PCI revision。
上述函数全部用固定参考驱动的原始指令执行验证，物理设备分支没有被执行。

## Linux 接入

`kernel/mt_tqx_topology.h` 校验信息页长度、magic、版本、平台和当前编码器支持的
1～8范围；失败不修改输出。8是本实现限制，不是新发现的硬件上限。

`mt_read_device_info` 在已有查询结果校验成功后调用 GEM 的锁内配置接口。
这里复用 probe 已持有的 `trial_lock`，避免嵌套获取同一互斥锁。
核心数保存在独立 `mt_gem_store.tqx_cores`，保留共享 `struct mt_guest` ABI。
初始化仅允许在没有BO时进行；重复的相同值接受，已安装数值的变化返回 `-EBUSY`，
防止已有状态区或上下文按旧布局被静默复用。

GEM `encode_tqx_dma` 输入核心数0表示使用查询结果；已查询时拒绝不同的显式核心数。
尚未安装信息页时，显式数量仍仅用于既有CPU编码测试，不能当作真实任务的准入证据。
更底层的原始编码器仍保留显式数量，以便做多核心布局对照。

## 验证

- `python3 scripts/verify-tqx-topology.py`：11组原始完整传递路径，包括1～8、0、9、
  `0xffffffff`，以及12个无效页头/长度/参数案例。Linux拒绝超出支持范围的数量。
- 保存的本机信息页 SHA256：
  `6163ff0648e2ec45fde070e39b8bc9b0c1686f71ac42d184cb074d70594eaa2b`，核心数1。
- `verify-runtime-integration.py`：11组回归、ASan/UBSan、W=1及共享ABI对照通过。
  GEM模型实际创建BO后验证禁止首次配置，并覆盖锁内配置、重复配置、冲突和坏页头。
- `verify-gem-kernel.py --kind gem --run`：126项真实内核RAM检查通过，增加自动选取
  核心数和冲突拒绝检查。临时模块已卸载，生产主模块未加载，设备仍未绑定。

这些结果确认信息字段与编码布局的关系。当前仍无MTT render节点或硬件加速。

## 状态初始化后续线索

状态分配链已进一步定位：`05aec0 → 05af2c → device vtable+0x170 → 092db8`。
`0931b8` 对 usage0/flags`0x10100` 选择类型2。平台初始化 `020a1c`
安装分配回调 `0219d0 → 041cc4`，类型名称表 `1411b4190[2]` 为 `ctxState`。
**这个回调取得已有上下文状态资源的地址，并不在该回调内分配或清零。**

`041cc4` 类型2的两条路径：opaque`+0x100 == 0`时从 opaque`+0xf8` 指向的
描述符读取 size`+8`、CPU`+0x10`、GPU`+0x18`；否则从 `*opaque+0x60`
资源读取 GPU`+0x10`、size`+8`，CPU映射从 opaque`+0x100`间接获取。
后续已用原始指令执行验证两条回调，确认保留状态内容；详见
[九对象与十一页上传](tqx-submission-upload.md)。资源初始语义仍需继续核对。

下一阶段仍需核对状态初始内容，接入 DMA/状态BO的映射上传，并衔接现有工作任务引用。
没有恢复、重置或Host操作。
