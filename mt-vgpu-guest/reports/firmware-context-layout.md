# 连接后上下文描述符

参考 `mtkm64.sys 14001ecdc -> 1400231ec`，适用于当前 Guest 三级页表分支。
`140016dcc` 只在 `140016218` 连接成功后调用此路径；不能用提前发布来解除连接停滞。

| 偏移 | 宽度 | 新建时内容与地址空间 |
| --- | --- | --- |
| 0x00 | 8 | 页表根 GPU PA，来自 `140018b20` |
| 0x08 | 8 | 0，含义尚未确认 |
| 0x10 | 8 | 固件 CPU 映射对应的 Guest GPA + layout+0x3c（当前队列偏移 0x6ddd0） |
| 0x18 | 8 | layout+0x58，固件 GPU VA |
| 0x20 | 8 | 0，含义尚未确认 |
| 0x28 | 8 | layout+0x30，当前队列 GPU VA |
| 0x30 | 4 | `1400229c0` 返回的设备配置值；来源是 GPU+0x950 指针指向结构的 +0x18，空指针时为 0 |
| 0x34 | 4 | 0 |
| 0x38 | 8 | 设备信息缓冲区的 Guest GPA |
| 0x40 | 8 | 平台内存窗口描述结构（GPU+0x408）的 Guest GPA，**不是 BAR2 基地址本身** |
| 0x48 | 8 | 0，含义尚未确认 |

描述符总长 0x50 字节，自己的 Guest GPA 通过 64 位 BAR1+0xf0 写入通知宿主。
参考代码将描述符缓存于 device+0x20+bank*8。重复调用时不重新分配，
不重填 root/queue/config，只更新 +0x38/+0x40 两个 GPA 再通知。
因此缓存描述符不能重新清零，未知字段也应保留。

`kernel/mt_fw_context.h` 已实现当前固定 Guest 布局的纯 CPU 构造和地址刷新；
GPU PA 和 GPU VA 限为 40 位，CPU GPA 保留独立地址空间，不应用 GPU 平移。
无效地址、长度与溢出在写输出前拒绝。尚未接入主模块或向设备发布。
运行时还需准备并保留正确的内存窗口描述缓冲区，确认 device_config 来源，
并解决描述符和两项所引用缓冲区的注册/撤销生命周期。

`python3 scripts/verify-fw-context.py` 执行原始构造、缓存、根地址查询和 Guest 发布
包装函数，只有分配、CPU 物理地址转换和 MMIO 被模型替代。
33 个新建与 33 个缓存刷新案例，逐字节比较 80 字节，另 18 个拒绝案例；
C helper 开启 UBSan。缓存案例随机化全部 80 字节、改变原输入，确认只刷新两项地址。
`build/firmware/context-example.bin` 的系统内存 GPA 是合成示例，不能直接写入设备。
证据见 `firmware-context-validation.json`；不证明宿主处理、固件执行或硬件加速。
